# Installed by Vercel for the Python function.

# Two things are pinned here, for two different reasons:
#
# 1. The rrip package itself, pulled from the public repo AT AN EXACT COMMIT.
#    It used to track @main, so the deployed API was whatever main happened to
#    be at build time -- including, when this was found, code without the AI
#    endpoint protection the docs described. A SHA makes each deploy
#    reproducible and reviewable: bump it deliberately, to a commit that passed
#    CI.
#
# 2. The core runtime dependencies, at the exact versions the test suite runs
#    against. rrip's own metadata declares these with >= floors (pyproject.toml,
#    [project].dependencies); left to float, a Vercel build could resolve a
#    newer release than CI ever tested -- which has already bitten once, when a
#    FastAPI minor changed how routers nest and silently voided a protection
#    test. Pinning makes the deployed versions the tested versions.
#    tests/test_function_requirements.py keeps this list in step with the floors.
#
# Only the CORE set is installed -- the `pipeline` extra (pandas, statsmodels,
# scipy, scikit-learn) is deliberately not requested, because the published
# tier never executes that code and it is 332.9 MB against Vercel's 250 MB limit.
